---
title: '!path'
tutorial: Basic PyWire
section: Directives
description: Create complex pages with deep-linking using !path dictionaries.
files:
  - path: pages/main.wire
    initial: |
      # Turn this !path directive into a dictionary
      !path "/menu"

      <div>
        <h1>This is the main menu</h1>
        <a href="/menu/settings">Go to Settings</a>
        
        <!-- Wrap settings in an `if` block targeting the settings path -->
        <h2>Settings:</h2>
        <ul>
          <li>Preferences</li>
          <li>Security</li>
          <li>Notifications</li>
        </ul>
      </div>
    solution: |
      !path {
        "menu": "/menu",
        "settings": "/menu/settings"
      }

      <div>
        <h1>This is the main menu</h1>
        <a href="/menu/settings">Go to Settings</a>
        
        {$if path.settings}
          <h2>Settings:</h2>
          <ul>
            <li>Preferences</li>
            <li>Security</li>
            <li>Notifications</li>
          </ul>
        {/if}
      </div>
successCriteria:
  - type: file_contains
    description: 'Define a !path dictionary'
    target: pages/main.wire
    pattern: '!path \{'
  - type: file_contains
    description: 'Wrap settings in {$if path.settings}'
    target: pages/main.wire
    pattern: '{\$if path.settings}'
  - type: browser_route_text
    route: '/menu/settings'
    description: 'Navigate to /menu/settings and see the settings list'
    pattern: 'Preferences'
pagesDir: pages
initialRoute: '/menu'
---

By default, files in the `pages/` directory are served at a route matching their filename. For complex components that handle multiple sub-views, you can use a dictionary with the `!path` directive.

### Your Task

1.  In `pages/main.wire`, change the `!path` directive to a dictionary mapping `"menu"` to `"/menu"` and `"settings"` to `"/menu/settings"`.
2.  Wrap the "Settings" `<h2>` and its `<ul>` list in a `{$if path.settings} ... {/if}` block.
3.  Click the "Go to Settings" link in the preview.

Notice how the same component instance can handle multiple routes, allowing you to maintain state across "page" changes!
